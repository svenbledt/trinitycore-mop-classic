# Phase 3/4, milestone M1: Pandaren and Monk on the Wandering Isle (plan, 2026-10-18)

Goal: create a Pandaren (any MoP class) or a Monk (any MoP race), start on the Wandering Isle (map 860)
with its NPCs and first quests, and play Monk basics. Decided with the user: content comes from TC `master`
**and** SkyFire 5.4.8, taking the best of both; the MoP talent/spec rework comes after M1.

## Starting point (checked 2026-10-18)
- Code: `CLASS_MONK = 10` exists; Pandaren 24/25/26 are not in `RACEMASK_ALL_PLAYABLE`.
- World DB (cata_classic TDB): Pandaren `playercreateinfo` rows for the classes other than Monk (race 24 starts on map 860); no Monk rows;
  map 860 has 0 creatures, 0 gameobjects and 0 quests.
- `upstream/master`: `Pandaria/zone_the_wandering_isle.cpp` (1682 lines), `Spells/spell_monk.cpp` (816 lines; retail Monk),
  and its TDB has the Wandering Isle spawns and quests.
- SkyFire 5.4.8: not available locally yet. The spellwork-548 MCP has 5.4.8 spell data.

## Reference data (local only, gitignored under `tools/mop-re/refs/`)
- MySQL schema `ref_master`: TDB 1210.26091, the TC master world DB.
- MySQL schema `ref_sfdb`: SFDB 26, plus SkyFire core `sql/updates/world` and `pending_updates/world` applied (78 files, 2026-10-18).
  SkyFire is GPL-3.0, so we use it for behaviour only; ask before copying code verbatim.

## Source rule (per item, highest first; user decision 2026-10-18)
1. **Retail sniffs** (5.5.4.70449) and the client's DB2s: ground truth for data, order, flow and packets.
2. **SkyFire 5.4.8** for MoP behaviour and data the sniffs don't show. Port its functionality as code rewritten in TC style
   (optimized, not copied verbatim); it beats master wherever master's retail-era version differs from MoP.
3. **TC master** for structure/API and as data fallback (IDs match the modern client).
Every imported row and script stays reproducible from `tools/mop-content/`, with the source cited in a comment.

## Steps
0. **References:** clone SkyFire 5.4.8 (core + world DB) read-only under `tools/mop-re/refs/skyfire` (gitignored), check its license,
   and get a TC master TDB to extract from. Nothing from these goes into the repo except our own conversion output.
1. **DB2 check (Phase 3):** compare the layout hash and fields of every store M1 needs against the 70449 files
   (WoWDBDefs where available), and fix `DB2LoadInfo.h`, `DB2Structure.h` and the hotfix schema. Also extract maps,
   vmaps and mmaps for map 860.
2. **Character create:** add Pandaren to the playable masks; neutral faction (team 24, faction choice at the end of the island;
   the packets come from the sniffs); Monk create data (spells, skills, items, action bars), with the race/class combinations
   taken from CharBaseInfo.
3. **Monk basics:** the Chi power type and Energy, plus Jab, Tiger Palm, Blackout Kick, Roll and Provoke. Behaviour follows
   SkyFire 5.4.8, checked against the 5.5.4 Spell DB2; the code uses TC master's script structure (`spell_monk.cpp`).
4. **Wandering Isle:** spawns, quests, gossip and SmartAI from the master TDB, extracted with a SQL script; area scripts from master's
   `zone_the_wandering_isle.cpp`; MoP-only gaps filled from SkyFire.
5. **Test:** create a Pandaren Monk and do the first quest chain. Use sniffs of the retail Wandering Isle (the sniffs already
   have a login there) and `sniffcheck` for any new packets.

## Step 3 status (2026-10-18): Monk basics, code + data done, not yet tested in the client
- **Chi/Energy: no core change needed.** The cata core already drives powers from DB2 like master: ChrClassesXPowerTypes gives Monk
  Mana 0, Energy 3, 10, 11, Chi 12 (power index 4); PowerType.db2 Chi (ID 14) = max 4, default 0, out of combat -0.1/s after
  10 s without Chi change (`UseRegenInterrupt`), nothing in combat. SkyFire 5.4.8 does the same (-1 Chi per 10 s out of combat).
  Energy: max 100, 10/s, haste-scaled. `Unit::Regenerate`, `EnergizeBySpell` (regen interrupt) and `SpellPower` costs handle the rest.
- **Spells (auto-learned, SkillLineAbility skill 829 AcquireMethod 2, level = SpellLevels):** 1 Jab 100780, Stance of the Fierce
  Tiger 103985 (+ passives 107500, 119650, 108977, 115074, 108562); 3 Tiger Palm 100787 (1 Chi); 5 Roll 109132; 7 Blackout Kick 100784
  (2 Chi); 12 hidden passive 115612; **Provoke 115546 is level 14**, not ≤10. List: `bun tools/mop-content/monk_spells.ts <db2 dir> [level]`.
  Class trainers are not needed (no trainer SQL).
- **Scripted** (`src/server/scripts/Spells/spell_monk.cpp`, master structure): Jab Chi (5.5.4 effect 1 is DUMMY bp1, 5.4.8 was
  ENERGIZE Chi; Fierce Tiger's PointsIndex1 +1 makes it 2), Roll (109132 → 107427 / backward 109131, run-back speed fix), Provoke
  (→ 116189, or 118635 on own Black Ox Statue). **Data-driven:** Tiger Palm, Blackout Kick (spec parts skipped: no specs yet), stance.
- **Data:** `sql/updates/world/mop_classic/2026_10_18_01_world.sql`: spell_script_names, plus a first-login cast of 103985 for
  Monks (Jab/Tiger Palm/Blackout Kick need a Monk stance; SkyFire casts it on every Monk login). Monks created earlier must click the stance once.
- **Checked against a retail 70449 sniff** (`m1.pkt`: fresh Pandaren Monk, levels 1-5, ~110 Jabs):
  - Jab: each hit casts **121588 Chi Energize** twice (1 Chi each, energize log 0 + OverEnergize 1 at cap); 5 misses gave none.
    The script now casts 121588 once per effect point (was a direct `EnergizeBySpell` from Jab).
  - Stance: 103985 is cast by the server at first login together with the create casts (also in SEND_SPELL_HISTORY). SQL kept.
  - Chi decay: first point lost 19-20 s after leaving combat, then 1 per 10 s (18:29:44 → 18:30:03/13/23/33). Matches the DB2 rule.
  - Chi max 4, Energy 100 (POWER_UPDATE). Tiger Palm learned at 3, Roll at 5 (LEARNED_SPELLS), nothing at 2 and 4.
  - Roll: run and run-back 21.175 (= 7 × 1.1 stance × 2.75), swim 12.986, flight 19.25, 800 ms, then back to 7.7/4.5. Aura 373
    `MOD_SPEED_NO_CONTROL` was NYI (run would have been 19.25), now handled in `Unit::UpdateSpeed` next to MOD_INCREASE_SPEED.
- **Open:** Jab weapon overrides: retail casts 108561 (2H Staff Override) at login and swaps Jab to 108557/115695 by weapon (not
  scripted; 100780 still works). Retail knows hidden passive 115612 (named "Expel Harm Driver", but a dummy aura on Paralysis/Purifier, level 12) at level 1;
  we learn it at 12. Expel Harm itself (115072) is an active level-26 spell.
  SMSG_LEARNED_SPELLS layout differs (spell at offset 13 after 3 u32 + 1 byte; known diff, `re-notes.md`).

## Step 4 status (2026-10-18): Wandering Isle, code + data done, not yet tested in the client
